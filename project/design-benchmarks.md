### What must NOT go there
- ⛔ **D2 raw reads** (any slice, any subsample) — cluster-only.
- ⛔ **10x barcode whitelists** — Cell Ranger licence clause 3 forbids redistribution. `whitelists/README.md` carries only: filename, the path inside a Cell Ranger install, `sha256`, line count, and the fallback mirror URL. CI uses a **synthetic 100k-barcode whitelist** generated with a fixed seed, which tests the code path without shipping 10x IP.
- ⛔ Anything > 200 MB in `ci/` — that tier is fetched on every realworld test run.
- ⛔ Cell Ranger BAMs (multi-GB); store only the derived `cb_counts.parquet` (barcode, n_reads, n_umis) extracted on the machine that has the BAM.

### Subsampling rule (and a correction to the stated one)

The brief says "sort by UMI, take the first N UMIs". **Lexicographic-first UMIs are biased** — you get only `AAA…`-prefixed UMIs, which correlates with poly-A artefacts and with the low-complexity tail of the UMI PWM, exactly the population whose behaviour we are measuring. Use a deterministic **hash partition** instead, which is unbiased, order-independent, and streaming:

```
keep(umi)  ⟺  blake2b_64(umi_seq, key="umi_data-v1") mod 10000 < K
```

with `K` chosen per dataset so the slice lands at the byte budget. Expected reads kept ≈ `total_reads × K/10000`. All reads of a kept UMI are kept — never a partial MIG. Recorded in each `manifest.json`:

```json
{"source_run":"SRR1200517","tool":"migec extract --mask …","hash":"blake2b_64","key":"umi_data-v1",
 "K":12,"n_umis":2041,"n_read_pairs":38774,"bytes_gz":8113244,
 "sha256_r1":"…","sha256_r2":"…","migec_version":"1.0.0"}
```

Budget: 2,000 UMIs / dataset ⇒ ~40k read pairs ⇒ ~8 MB gz each ⇒ `ci/` ≈ 50 MB. Whole repo target ≤ 3 GB LFS (dominated by `synthetic/calib_sim`).

## 5. Metrics

### 5.1 UMI grouping accuracy (D12, D13, `synthetic/tenx_sim` — truth only exists on simulated data)

Contingency table `n_ij` = reads in true molecule *i* ∩ called group *j*; `a_i = Σ_j n_ij`, `b_j = Σ_i n_ij`, `n = Σ n_ij`.

```
TP = Σ_ij C(n_ij,2)
FP = Σ_j  C(b_j,2) − TP
FN = Σ_i  C(a_i,2) − TP

pair_precision = TP / (TP + FP)
pair_recall    = TP / (TP + FN)

        Σ_ij C(n_ij,2) − [Σ_i C(a_i,2) · Σ_j C(b_j,2)] / C(n,2)
ARI = ───────────────────────────────────────────────────────────────
      ½[Σ_i C(a_i,2) + Σ_j C(b_j,2)] − [Σ_i C(a_i,2) · Σ_j C(b_j,2)] / C(n,2)

mol_count_rel_err = (M̂ − M) / M
```

Report **all three**. ARI is the comparability metric (Calib publishes it). Precision/recall is the diagnostic: low precision = over-merging (distinct molecules collapsed), low recall = splitting.

**Which error is costly, per readout:**
- **scRNA-seq quantification** → over-merging undercounts molecules and compresses expression. Optimize **pair_precision** and `|mol_count_rel_err|`.
- **Consensus error correction** → splitting only shrinks MIGs (weaker correction, no false alleles); merging creates chimeric consensuses and **false variants**. Optimize **pair_precision**; accept recall loss.
- **UMI collision handling** (the multiple-groups-per-UMI feature) is measured here directly: on D12 with `barcode_length=4`, collisions are forced, so `pair_precision` with vs. without sequence-aware splitting is the ablation.

### 5.2 Consensus base accuracy (D5 8E5, D1/D2 spike-ins, D3 wildtype positions)

Let `S` = set of assayed reference positions, excluding known truth-variant sites (`hd734_variant_metadata.tsv`, spike-in junctions, HIV polymorphic sites).

```
e_out = Σ_{consensus bases at S} 1[base ≠ ref] / Σ_{consensus bases at S} 1
e_in  = Σ_{raw read bases at S}  1[base ≠ ref] / Σ_{raw read bases at S}  1
suppression S_f = e_in / e_out
```

`e_out` reported with a **Wilson 95% interval** (never Wald — at e_out ~ 1e-5 the normal approximation is wrong):
```
CI = ( p̂ + z²/2n ± z·sqrt( p̂(1−p̂)/n + z²/4n² ) ) / (1 + z²/n),  z = 1.96
```

**The headline claim:** `e_in ≈ 10⁻² … 10⁻³ → e_out ≤ 10⁻⁵`, i.e. `S_f ≥ 100`, on a clonal template.

**Stratify by MIG size bucket** `{1, 2, 3–4, 5–9, 10–19, 20–49, 50–99, ≥100}`. This is the direct test of the "keep low-coverage UMIs" requirement: the 3–4 and 5–9 buckets must be *retained* and must be *honestly qualified*, not dropped.

**Quality calibration** — the gate that validates the 10⁻⁵–10⁻⁶ cap:
```
ê(Q)   = n_errors(Q) / n_bases(Q)
ECE    = Σ_Q (n_Q/N) · | ê(Q) − 10^(−Q/10) |
anticonservative(Q) ⟺ ê(Q) > 2 · 10^(−Q/10)   (only judged when n_Q ≥ 1000)
```
Anti-conservative quality is the costly error here: a downstream caller trusting a Q60 base that is really Q30 emits false variants. Over-conservative quality only costs sensitivity.

### 5.3 Clonotype level (D1: 3 IGH; D2: 12; D13: 12 synthetic)

```
recall    = |called ∩ truth| / |truth|
FP_count  = |called \ truth| filtered to ≥ 2 MIGs
FP_rate   = FP_count / (consensus reads / 10⁶)
freq_err  = median over truth clonotypes of |log10( f̂ / f_truth )|
```
Compare against MIGEC v1 **at the same `minCount`** — otherwise the comparison is a threshold comparison, not an algorithm comparison. Sweep `minCount ∈ {1,2,3,5,10}` and report the recall-vs-FP frontier, as `2026-arda-benchmark/scripts/pr_frontier.py` already does.

**Costly error: false-positive clonotypes.** A repertoire method that invents clonotypes is unusable; missing a 1% clone is recoverable by sequencing deeper.

### 5.4 10x (D7, D8)

```
jaccard_cells           = |A ∩ B| / |A ∪ B|          A = our called cells, B = CellRanger filtered barcodes
per_read_cb_concordance = #reads where our corrected CB == CellRanger CB tag / #reads with a CellRanger CB tag
spearman_umi            = Spearman ρ on log1p(UMIs per cell) over A ∩ B
median_abs_log2_ratio   = median | log2( n̂_c / n_c ) |  over c ∈ A ∩ B
```
`per_read_cb_concordance` is the sensitive metric (it sees every correction decision); `jaccard_cells` is coarse and saturates. Extract the CB/CR/UB/UR tags once from the published `possorted_genome_bam.bam` into `cb_counts.parquet` — do not ship the BAM.

**Costly error: calling empty droplets as cells** (precision on the cell set) — it injects ambient RNA into the count matrix. Missing a low-RNA cell is visible and correctable.

**Doublet detection has no truth in D7–D9.** Either add the CellPlex `20k_Mouse_PBMC_Splenocyte_5p_gem-x_multiplex` set (CMO tags give per-cell doublet labels) or **cut doublet validation from v1** and validate only on `synthetic/tenx_sim`, where we inject doublets at a known rate. Recommendation: **cut from v1**, validate synthetically, flag as unvalidated on real data.

### 5.5 Speed and memory


## 8. What I would cut from v1

| cut | reason | replacement |
|---|---|---|
| Duplex-Seq-Pipeline as a comparison tool | snakemake + conda + BLAST + bwa + a UCSC genome, ships no test FASTQ; the whole pipeline is out of our scope | keep **duplex α/β tag support** as a feature (D4 masks), validate against MAGERI's published D4 histogram (G9) |
| IonTorrent 7mix (D14) | unpaired, indel-dominated; needs an indel-tolerant consensus we are not building | — |
| 10x melanoma (D10) and mouse splenocytes (D9) | D10 is a different read structure (TotalSeq-C), D9 is a third copy of D7's chemistry | D7 + D8 only |
| 40 of 42 runs of the PCR-error assay (D6) | 51.5 GB to source one constant | 1–2 runs, solely to calibrate the 10⁻⁵–10⁻⁶ quality cap |
| starcode-umi / cd-hit-est / rainbow / du novo | Calib already published their ARI on D12 | cite Calib's table |
| Running Cell Ranger ourselves | 64 GB RAM, references, days of compute, for an output 10x already publishes | use the published `filtered_feature_bc_matrix` / `molecule_info.h5` |
| Doublet-detection validation on real 10x | no truth in D7–D9 | validate on `synthetic/tenx_sim` only; ship the feature marked "not validated on real data", or add the CellPlex dataset in v1.1 |
| ARI on any real dataset | there is no read→molecule truth on real data — an ARI computed against another tool's output is a concordance, not an accuracy | report it as `tool_concordance_ari` in a separate column, never as accuracy |
| A bespoke read simulator for grouping | `calib simulate` already exists, is published, and produces the truth format Calib's own scorer consumes | write our own simulator **only** for cell barcodes + doublets (~120 lines), which Calib does not model |

**One thing I would add that is not in the brief:** G8 (thread-count determinism). It is nearly free to test on the `ci/` tier and, with `std::thread` over disjoint ranges and no synchronisation (the arda C++ style), non-determinism in output ordering or in tie-breaking during consensus is the most likely silent defect in this design.
